Architecture: vectors are buffered *across* documents (not per-document as before) and flushed in batches of exactly `UPSERT_BATCH_SIZE = 200`, sent via `async_req=True` with up to `POOL_THREADS = 30` concurrent in flight. Checkpointing (`checkpoint.json`, atomic write via temp-file + `os.replace`) stores the last document_id *fully confirmed* upserted along a deterministic `ORDER BY document_id` sequence (added to `ingestion/extract_sql.py`); because batches complete out of order under concurrency, the checkpoint only advances through a *contiguous* confirmed prefix (`advance_watermark`), never jumping ahead on a lucky out-of-order completion — this is what makes "resume exactly where it left off" actually correct, not just fast. Caught and fixed a real memory risk before running anything: the original `extract_documents()` would have loaded all ~2.5GB of full document content into a single Python list at once, which is dangerous on a machine that has already hit low-memory kills this session (~1-1.5GB free of 16GB).
